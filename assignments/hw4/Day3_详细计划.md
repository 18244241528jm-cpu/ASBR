## 上午块 A：过程噪声在 EKF 里到底管什么（约 1-1.5 h）

### A1. 和观测噪声 $R$ 的分工

| 矩阵 | 含义（直觉） | Day 3 谁优先动 |
|------|----------------|----------------|
| **$Q$ / `WMWt`**（过程噪声） | 预测有多“松”：车模型、指令噪声、未建模扰动 | **主战场** |
| **$R$**（`meas_evaluate_R`） | 传感器有多“信” | 仅在位置/姿态融合明显不合理时 **微调** |

- **$Q$ 偏大**：更信观测，轨迹更容易被 GPS/IMU **拽动**，可能对延迟/映射误差敏感。  
- **$Q$ 偏小**：更信模型，轨迹更 **平滑**，但真车加速/打滑时容易 **滞后**。  
- 作业要求 **`WMWt` 与指令 $(v,\omega)$ 相关**：静止与高速转弯时过程不确定性不同，对角元素常随 $|v|$、$|\omega|$ **放大**。

打开 `ekf_models.cpp` / 头文件，确认：

- [ ] 输出矩阵 **对称、正定**（常见做法：对角元素 **严格为正**，必要时加小下界）。  
- [ ] 使用了 **当前控制量** $v$、$\omega$（或骨架提供的等价变量），而不是常数阵一用到底。  
- [ ] 维度与 BFL 骨架一致（与状态维、噪声维匹配，**不要凭感觉多一维**）。  
- [ ] 与 Day 1 的 **$\Delta t$** 一致：若噪声定义与离散时间步有关，不要和骨架假设打架。

## 上午块 B：系统化调 `WMWt`（约 2.5-3.5 h）

### B1. 调参顺序（建议严格执行）

1. **固定** `meas_evaluate_R` 为 Day 2 的“中等保守”一版。  
2. 只改 **`sys_evaluate_WMWt`**：  
   - 先调 **与 $v$ 相关** 的对角项（影响沿车体方向推进时的位置不确定性）。  
   - 再调 **与 $\omega$ 相关** 的项（影响转弯时姿态与横向耦合）。  
3. 若出现 **GPS 一更新就猛跳**：先略 **增大** GPS 块在 $R$ 中的方差（小步），再回到 $Q$；仍乱则回头查 **$h_{gps}$ / $H_{gps}$**。  
4. 若出现 **姿态抖动**：略 **增大** IMU 块在 $R$ 中的方差或 **减小** 对应 $Q$ 中姿态相关项（二选一、小步）。

### B2. 每组参数要做的最小实验（各约 3-5 分钟）

每组参数至少跑 **2 条轨迹**（同一块 B 内可共用）：

| 轨迹 | 操作 | 看什么 |
|------|------|--------|
| **直线** | 匀速前进 10-20 m | `/posterior` 与真值 **位置** 是否贴、有无滞后 |
| **转弯** | 固定 $\omega$ 转 90°-180° | yaw 是否跟、位置是否 **外甩/内切** 异常 |
| **坡面** | 上一小段坡再下 | $z$、pitch 是否合理（不要求完美，但勿发散） |

记录方式（任选其一，但要 **可复现**）：

- 笔记本表格：参数版本号、现象关键词（滞后/跳变/抖）、是否通过。  
- 或 **ros2 bag** 录一段（见块 D）。

### B3. 常见现象与优先旋钮

| 现象 | 优先尝试 |
|------|----------|
| 位置明显 **滞后** 于真值 | 略 **增大** 与平移/速度相关的 $Q$ 分量，或略 **减小** GPS 方差（小步） |
| GPS 更新时 **突跳** | 略 **增大** GPS $R$；检查 $h_{gps}$ 线性近似是否过粗 |
| 转弯后 **yaw 漂** | 检查 Day 1 的 $\dot\psi$ 与 $A$；调 **$\omega$ 相关** $Q$ 或 IMU $R$ |
| 全程 **数值爆炸** | 回到 Day 1/2：$A$、$H$、$R$ 是否正定，有无未初始化元素 |

## 下午块 C：Expert Challenge 指标怎么算（约 1-1.5 h）

### C1. 作业口径（与 PDF 对齐）

- 真值：从仿真读取（例如 `ign topic -e -t /model/robot/pose`），取 **base_link**（或作业说明的帧）的 **位置**。  
- 估计：`/posterior` 中 EKF 给出的 **位置**（与骨架消息字段一致，需在代码或 `ros2 interface show` 里确认字段名）。  
- 误差（每一时刻）：

$$
e = p_{\mathrm{est}} - p_{\mathrm{true}} \in \mathbb{R}^3,\quad \|e\|_2 = \sqrt{e_x^2 + e_y^2 + e_z^2}
$$

- **Expert**：在峡谷里 **驾驶多段轨迹**，使 **$\|e\|_2$ 的时间平均** **小于 0.5 m**。

**纯文本**：

```text
ex = est_x - true_x
ey = est_y - true_y
ez = est_z - true_z
norm_e = sqrt(ex*ex + ey*ey + ez*ez)
mean_norm = average(norm_e over time window)
目标: mean_norm < 0.5
```

### C2. 实操建议（从易到难）

**方法 1：录 bag 离线算（推荐）**

```bash
# 终端 A：已 launch 仿真 + 你的 EKF
ros2 bag record /posterior /tf /tf_static
# 若 posterior 不含真值，真值单独从 ign 导出或另起节点记录
```

若 bag 里 **没有** 与 posterior 时间对齐的真值，可：

- 用 **近似同一时间戳** 的两次 echo 手工对齐（粗糙），或  
- 写 **短脚本**（Python + rclpy）同时订阅后验与真值 topic，对齐后写 CSV。

**方法 2：小脚本在线打印误差（够用即可）**

思路：同一节点内订阅两个源，用 **最近邻时间** 或 **外推一步** 对齐，每秒打印 `mean` 的滑动平均。

检查项：

- [ ] $p_{\mathrm{est}}$ 与 $p_{\mathrm{true}}$ 在 **同一世界系**（或已静态 TF 变换到同一系）。  
- [ ] 若 yaw 对上了但位置差一固定偏置，说明有 **原点/偏置** 未对齐，应在 **GPS 映射或初值** 上修，而不是盲目调噪声。

### C3. Expert 当天测试流程（建议）

1. **热身 2 分钟**：平地直线 + 小转，看 `/posterior` 是否正常。  
2. **峡谷慢速 5-10 分钟**：覆盖 **上下坡、左右弯、窄路**，速度别过快（仿真动力学与传感器噪声都更友好）。  
3. **分段统计**：每 1-2 分钟一段算 **段内平均 $\|e\|_2$**，避免“只有一段极好、另一段爆表”。  
4. 若 **均值卡在 0.5-0.8 m**：  
   - 先确认 **GPS 线性映射** 是否在各象限一致；  
   - 再微调 **GPS 块 $R$** 与 **平移相关 $Q$**（小步、单次只动一个旋钮）。
